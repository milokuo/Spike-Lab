# M2.2 輸入重設計規格（orchestrator 拍板版）

> 由 orchestrator（Fable）產出，supersedes spike_lab_spec_v0.2.md §4 的按鍵定義與 docs/m2.1_plan.md 的跳躍協定。
> 打破舊協定完全允許（無既有部署）。實作時以本文件為準；未提及處沿用 m2.1 現狀。

## 0. 動機（實測回饋）
- 蓄力跳「放開才跳」預測太難 → 改按下即跳、按住越久越高。
- J/K/L 應為**狀態切換**，實際出手是**滑鼠左鍵**（按住蓄力、放開出手）。
- J（接球）判定要寬鬆、過遠自動嘗試飛撲（機率接起）。
- 發球要站場外。
- 需要明確的目前模式顯示。

## 1. 跳躍（variable jump，按下即跳）

### 1.1 行為
- Space **按下瞬間**：若在地面且耐力 ≥ `JUMP_STAMINA_BASE` → 立即以 `JUMP_V0` 起跳，扣 `JUMP_STAMINA_BASE`。
- **按住期間**：僅在「上升段且起跳後 ≤ `JUMP_BOOST_MAX_S`」內，重力乘 `JUMP_HOLD_GRAVITY_MULT`（<1，延長上升＝跳更高）；此期間每秒另扣 `JUMP_STAMINA_HOLD_PER_S` 耐力（耐力歸零則 boost 中止）。
- **放開**（或超過 boost 窗、或開始下落）：恢復全重力 `JUMP_GRAVITY`。
- 落地（y≤0 且 vy<0）前不得再跳。輕點＝小跳，按滿＝最高跳，峰值封頂。

### 1.2 常數（shared/constants.ts；取代 m2.1 的 V0_MIN/V0_MAX/CHARGE_RATE/STAMINA_MIN/MAX 蓄力跳體系）
```
JUMP_V0 = 4.2               // u/s，按下即用
JUMP_GRAVITY = 18           // u/s²（沿用）
JUMP_HOLD_GRAVITY_MULT = 0.45
JUMP_BOOST_MAX_S = 0.30
JUMP_STAMINA_BASE = 6
JUMP_STAMINA_HOLD_PER_S = 10   // 最多再扣 ~3
// 推導：輕點 apex ≈ 0.49u（手 3.04 > 網 2.43），按滿 apex ≈ 1.09u（手 ≈ 3.64）
```

### 1.3 純函數（shared/kinematics/jump.ts 重寫；舊 jumpChargeToV0/startJump(charge) 移除）
```ts
interface JumpState { y: number; vy: number; airborneS: number }
startJump(): JumpState                                  // {y:0, vy:JUMP_V0, airborneS:0}
stepJump(s: JumpState, dtS: number, held: boolean): JumpState  // 不可變，含 boost 窗/重力規則
isLanded(s: JumpState): boolean
jumpHoldStaminaCost(dtS: number, boosting: boolean): number
```
Server 與 client 預測都只准呼叫這一份。

### 1.4 協定
- 刪除 `JumpCommand`。`InputFrame.jump: JumpCommand|null` → **`jumpHeld: boolean`**（每幀回報按住狀態）。
- Server 以 `jumpHeld` 的 rising edge 觸發起跳（grounded gate＋耐力檢查），每 tick 用該幀 `jumpHeld` 跑 `stepJump`。
- Client 在 keydown 當下本地立即起跳預測；reconciliation 沿用 m2.1 策略（僅落地時硬同步垂直）。

## 2. 模式切換 ＋ 左鍵出手

### 2.1 行為
- 玩家有 `touchMode ∈ 'dig'|'set'|'spike'`，**預設 'dig'**，死球重置為 'dig'。
- J/K/L keydown＝切換模式（隨時可切、含左鍵蓄力中；切換即時生效）。
- **滑鼠左鍵按住**＝蓄力（沿用 CHARGE_RATE 累積、蓄力減速、耐力消耗規則）；**放開**＝出手：
  - 以**放開瞬間**的 `touchMode`、WASD 方向鍵狀態（dirInput，玩家視角座標，過 viewToWorld）、蓄力值組成 `TouchIntent` 送出。
  - `clientTime` ＝ **放開瞬間**時間戳 → f_timing 的 Δt 在放開那一刻判定（正式解決 m2.1 G3：判定時刻＝出手時刻）。
- 發球階段：僅發球者可出手，同樣左鍵蓄力/放開；`SERVE_MIN_CHARGE` 地板沿用。
- 左鍵事件須忽略落在 UI（大廳/按鈕）上的點擊；`contextmenu`/選字等瀏覽器預設要擋。

### 2.2 協定
- `InputFrame` 新增 `touchMode: TouchMode`（每幀回報；server 寫入權威狀態）。
- `PlayerSnapshot` 新增 `mode: TouchMode` → 所有客戶端可渲染任何玩家目前模式（可讀性/心理戰，呼應 spec 支柱 3）。
- `TouchIntent.mode` 語意不變（＝放開瞬間的模式）；server 仍以自身權威 mode 交叉驗證（不符則以 server 端為準或拒絕，擇一實作並註明）。

### 2.3 模式顯示（client）
- HUD 顯著徽章：`[J] 接球`／`[K] 舉球`／`[L] 殺球`（目前者高亮）。
- 角色膠囊 tint：dig=藍、set=綠、spike=紅（本人＋遠端玩家都依 snapshot.mode 上色）。

## 3. J（dig）寬鬆判定 ＋ 飛撲（dive）

### 3.1 dig 專屬距離曲線（僅 mode='dig' 適用；set/spike 沿用 §6.2 原曲線）
```
DIG_SWEET = 0.7        // ≤ → f_distance = 1.0（原 0.5）
DIG_DECAY_END = 1.5    // 線性 1.0→0.5（原 1.2）
DIG_REACH_MAX = 2.2    // 0.5→0.1（原 1.8）；≤此值為正常接球
```

### 3.2 飛撲（server 權威）
- 放開左鍵時（mode='dig'）回溯距離 d ∈ (DIG_REACH_MAX, DIVE_REACH_MAX] → 自動判為**飛撲嘗試**：
```
DIVE_REACH_MAX = 3.4
p_success = lerp(0.8 @d=2.2 → 0.2 @d=3.4)   // 線性、clamp
成功：quality = DIVE_QUALITY = 0.35（固定低品質），球依 dig 意圖推向最近隊友（1v1 自舉 fallback 沿用）
失敗：無觸球（whiff），球繼續飛
成敗皆：玩家向回溯球點方向前撲（位移 ≤ DIVE_LUNGE_MAX = 2.0，過網線 clamp），
        移動鎖定 DIVE_LOCK_S = 0.8，扣 DIVE_STAMINA = 15（不足則不觸發飛撲、判 whiff）
擲骰：server 端以現有 rng seed 體系決定，結果寫進 TouchResult 廣播
```
- `TouchResult` 新增 `outcome?: 'dive_success' | 'dive_fail'`；client 演出：前撲動畫（膠囊傾倒前衝即可）＋成功「救球!」/失敗「撲空!」回饋字＋失敗音效缺省可略。
- d > DIVE_REACH_MAX：純 whiff（現狀）。
- 垂直 reach gate：dig/飛撲對「球高」的限制放寬到 `DIG_VERTICAL_MAX = STANDING_REACH`（飛撲救的是低平球，不需跳）；set/spike 沿用現有 gate。

## 4. 發球站場外
- `SERVE_SPAWN_Z = ±(COURT_HALF_LENGTH + 0.8) = ±9.8`（m2.1 為 ±6.5，場內 → 改場外）。
- 發球者與持球演出都在此位置；發球後移動自由（可跑回場內），場外站立不違規。
- 發球彈道常數需重驗：從 z=9.8 起，`SERVE_MIN_CHARGE` 檔必須穩定過網、落在對場內；滿蓄可出界（維持風險設計）。若 0.35 地板不夠，允許上調 SERVE_MIN_CHARGE 或微調發球弧線，以「最低檔必過網」為驗收。

- **WP1 shared**（機械）：常數增修、jump.ts 重寫（§1.3）、InputFrame/PlayerSnapshot/TouchResult 型別、dig 曲線與 dive 機率純函數（`digDistanceQuality(d)`, `diveSuccessProbability(d)`, 皆有測試）、viewSpace 不動。測試：輕點/按滿 apex 單調且封頂、boost 窗過期無效、dig 曲線斷點、dive 機率端點與 clamp。全綠＋覆蓋率 ≥80%。
