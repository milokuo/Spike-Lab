# M2.6 隊伍空位制、發球輪換、球影、渲染效能 規格（orchestrator 拍板版）

> 增補於 m2.5 之上。未提及處沿用現狀。

## 1. 大廳隊伍空位制（lobby 階段限定）
- 每隊 **6 個格位**（slot index 0..5），房間 maxClients 4 → **12**。
- 資料（延伸現有 packages/shared/src/types/lobby.ts，以現有型別為基礎改）：
```ts
interface TeamSlot { side: 'A'|'B'; index: number /*0..5*/; playerId: string|null; name: string|null }
// LobbyState 改為攜帶 slots: TeamSlot[]（12 筆全量）＋現有 hostId/canStart 等欄位
```
- 新 channel `CH.REQUEST_SLOT`，payload `{ side:'A'|'B', index:number }`：僅 lobby 階段有效；目標格位必須為空；合法則把該玩家移過去（原格位清空）並廣播新 LobbyState；非法靜默忽略。
- 進房自動分配：人少的隊伍（平手進 A）的最低空位。離房清空格位。
- 開賽條件沿用：每隊 ≥1 人、host 按開始。**格位順序＝發球輪轉順序（§2）**。
- client UI：左右兩欄（A 藍 / B 紅）各 6 張格位卡；有人＝顯示名字（自己高亮＋「你」標記）、空位＝虛線卡寫「點擊加入」；hover 效果；start 按鈕與房碼沿用。切隊即點對面空格，不需額外按鈕——要讓非技術玩家一眼懂。

## 2. 發球輪換（FIVB 改編）
- 每隊維護 rotation order ＝ 開賽當下格位 index 升序的玩家列表；per-team `rotationIdx` 起始 0。
- 規則：
  - 開賽：A 隊 rotationIdx=0 的玩家發第一球。
  - 同隊連續得分 → **同一人連續發球**（不輪轉）。
  - side-out（非發球隊得分取得發球權）→ 該隊 `rotationIdx = (rotationIdx+1) % teamSize` **後**由新 idx 玩家發球；例外：該隊**本局第一次**取得發球權時不前進（從 idx 0 開始）——等價於正式規則「取得發球權才輪轉」在小隊伍的縮影。
  - 玩家中離：從 order 移除、idx 取模修正；單人隊伍恆為該人。
- server 權威；發球者站位/持球演出沿用現狀（servingId 換人即可）。

## 3. 模式不重置
- 移除 server 死球時 all-players mode 重置為 'dig' 的行為；client 端 deadball 本地重置一併移除。模式唯一改變途徑＝玩家按 J/K/L。gameover/回大廳也不重置。

## 4. 球影（client only）
- 半透明黑色圓形 blob（CircleGeometry ~0.55u、opacity 基準 0.4），貼地（y=0.01，renderOrder 防 z-fight），XZ 跟隨球的渲染位置每幀更新。
- 高度衰減：opacity = 0.4 × clamp01(1 − ballY / 8)，半徑隨高度微增（×(1 + ballY×0.05)）——越高越淡越散。
- 發球持球時也顯示（幫發球者對位）；死球/無球時隱藏。

## 5. 渲染效能（client only，回應「朋友內顯吃滿」）
- `WebGLRenderer({ antialias: true, powerPreference: 'high-performance' })`。
- `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 1.5))`；resize 時同樣封頂。
- 確認 render loop 用 rAF（分頁隱藏自動節流）；nametag/臉 CanvasTexture 禁止每幀重繪（僅內容變更時 needsUpdate）。
- README 加一段「效能提示」：瀏覽器選 GPU 機制＋Windows 圖形設定指定高效能 GPU。
