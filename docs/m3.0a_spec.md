# M3.0a — 飛行模型 v2 地基：確定性積分器＋旋轉（2026-07-06）

妖球物理三部曲之一（0a 地基＋預設旋轉 → 0b 觸點 bias 輸入 → 0c 飄浮球）。
本規格拍板依使用者決策：**定步長積分器地基／出手瞬間方向鍵 bias（0b）／誇張街機手感**。

## §0 設計哲學（使用者拍板，恆常有效）

**意圖與執行分離**：
- 觸點／瞄準＝**意圖**（intent）——玩家指到哪就是哪。
- 時機品質＝**執行忠實度**（fidelity）——決定意圖被多準確地執行。
- 打歪＋時機完美＝完美執行錯誤意圖（球又快又扎地飛向錯的地方）。
- 時機差＝執行走樣：方向誤差錐＋力量衰減＋旋轉散掉。**fidelity 只加噪、永不糾偏意圖**。

## §2 飛行模型（WP-P0 實作）

- **積分**：semi-implicit Euler，`PHYSICS_DT = 1/240 s`。先更新 v 再更新 p。
- **力項**（世界座標，加總）：
  1. 重力：沿用 shared 既有 GRAVITY 值（P0 內部常數引用，不改原檔）。
  2. 阻力：`a_d = −DRAG_K · |v| · v`（二次阻力）。Cd 以函數注入點呈現
     （P0 為常數；0c 的速度相依「阻力危機」曲線換這個函數即可）。
  3. Magnus：`a_m = MAGNUS_K · (ω × v)`。
  4. 旋轉衰減：每步 `ω ×= SPIN_DECAY_STEP`（launch 時以 `exp(−SPIN_DECAY·dt)` 算一次
     的預乘因子；step 迴圈內只有 + − × ÷ 與 sqrt，禁用超越函數）。
- **確定性紀律**：固定 dt、固定運算順序、無分支依賴浮點比較的路徑差。雙端 ulp 級
  差異可容忍（事件判定 server 權威）；同引擎兩次執行必須 bit 一致（測試斷言）。
- **API**（P0 全部 pure，無 I/O）：
  ```ts
  interface FlightLaunch { origin: Vec3; velocity: Vec3; omega: Vec3; startMs: number }
  flightStateAt(launch, tMs): { pos: Vec3; vel: Vec3; omega: Vec3 }   // 內部增量快取
  firstFlightEvent(launch, bounds): { type: 'ground'|'net'|'out'; tMs; pos; vel; omega }
  ```
  事件偵測＝步進偵測穿越＋固定次數二分精修（BISECT_ITERS=20，確定性）。
  net 平面／場界參數由呼叫端傳入（P0 不 import court 常數，維持零耦合）。
- `FlightLaunch` 是 P0 內部型別；P1 才併入 wire 的 BallLaunch（加 `omega` 欄位）。

## §3 ω 符號約定＋真值表（本輪最重要的守門員）

- ω＝世界座標角速度向量，**右手系**。推導錨點（測試須含此案例）：
  球沿 +Z 飛、上旋（球頂表面向 +Z 轉）⇒ **ω = +X̂**；Magnus `ω×v = (0,−vz,0)` 向下壓。✓
- 觸擊層的 spin 意圖一律在**視角空間**定義（top/back/side-L/side-R），經 shared 單一
  轉換入口變世界 ω（P0 新增 `spinIntentToWorld(intent, side, yaw)`，約定對齊
  moveToWorld：yaw=null＝第三人稱 side 鏡像）。**鏡像只准存在這個入口**（鐵律 2 延伸）。
- **真值表測試**（cameraBasis 等級，血淚史強制）：枚舉 side A/B × {top, back, side-L,
  side-R} × yaw {null, 0, π/2}，斷言世界 ω 向量、Magnus 加速度方向、以及「防守方
  螢幕視角看到的彎向」三者全對。另含殘留狀態案例（stale yaw 傳入）。
- 其餘 P0 測試：ω=0 且 DRAG_K=0 時與解析拋物線誤差 <1e-9；對 RK4（dt/16 參考實作，
  寫在測試檔內）全程誤差 <2cm；兩次執行 bit 一致；事件邊角（擦網頂、近零 vy 落地、
  出界與落地同 tick）；旋轉衰減單調。

## §4 觸擊忠實度模型（P1 實作，本輪拍板公式）

- intent = { dirIntent（既有瞄準約定）, ωIntent（0a＝模式預設：spike→topspin×蓄力、
  發球→量角器側旋；0b 加 bias 鍵）, powerIntent（蓄力） }。
- `f = fidelityOf(deltaMs)`：以既有評級窗為底的遞減曲線
  `f = clamp01(1 − (|Δ|/FIDELITY_WINDOW_MS)^FIDELITY_EXP)`，PERFECT 帶內 f=1；
  過蓄懲罰乘進 f（沿用 overchargeQualityMult 曲線）。
- 執行（順序固定）：
  1. 方向：繞隨機軸偏轉 `θ_err = (1−f) · ERR_CONE_MAX_RAD · η`，η∈[−1,1] 為
     seed(playerId, serverTime) 的確定性雜湊噪音（可測試重放）。
  2. 力量：`|v| ×= POWER_FLOOR + (1−POWER_FLOOR)·f`。
  3. 旋轉：`ω ×= f^SPIN_FIDELITY_EXP`（旋轉最吃執行精度）。
- TouchResult 的 grade 顯示不變；wire 不加欄位（0a）。

## §5 起始參數表（誇張街機基調；全部 tunable，P1 併入 shared/constants.ts）

| 常數 | 起始值 | 手感意圖 |
|---|---|---|
| PHYSICS_DT | 1/240 s | 積分穩定度 |
| DRAG_K | 0.020 /m | 殺球全程掉速 ~8%，長球尾段明顯變軟 |
| MAGNUS_K | 0.022 | 滿旋殺球額外下壓 ≈0.8g，一眼可讀的下扎 |
| SPIN_MAX | 45 rad/s | 旋轉上限（clamp 於觸擊層） |
| SPIN_DECAY | 0.35 /s | 1 秒掉 ~30%，長 rally 彎度自然鈍化 |
| ERR_CONE_MAX_RAD | 18° | 最爛時機的方向散布 |
| POWER_FLOOR | 0.55 | 爛時機也保留 55% 力量（可玩性下限） |
| SPIN_FIDELITY_EXP | 1.5 | 時機稍差旋轉先散，方向後散 |
| FIDELITY_EXP | 1.6 | 評級窗內外的手感斜率 |
| BISECT_ITERS | 20 | 事件精修（確定性固定值） |

## §6 視覺藍圖（P1，client；玩法/視覺常數嚴格分離）

球面縫線紋理＋依 ω client 端積分自轉（純視覺）；彎軌跡由殘影 trail 自然呈現；
|ω| 高於閾值時 trail 略加濃（視覺常數）。不加任何判定耦合。
